# PBI-014 ログインする

## ユーザーストーリー

As a ユーザー
I want アカウントでログインしたい
So that 自分の村や住人データに安全にアクセスできる

## 背景 / 目的

全PBIの認証前提となる基盤機能。ログインなしでは「自分の村のみ表示」「他ユーザーの村への編集ガード」など所有者ベースの制御が実現できない。

## スコープ

- 含む
  - ログイン画面の表示
  - 認証情報の検証・セッション確立
  - 未ログイン状態でのアクセス時にログイン画面へリダイレクト
  - ログアウト
- 含まない
  - ユーザー登録（新規アカウント作成）
  - パスワードリセット
  - ソーシャルログイン（OAuth）
  - 二段階認証

## ユースケース

### メイン

1. ユーザーがログイン画面にアクセスする
2. 認証情報を入力して「ログイン」を実行する
3. 認証が成功しセッションが確立される
4. トップ画面（村一覧など）にリダイレクトされる

### 代替

- 認証情報が誤っている場合 → エラーメッセージを表示

### 例外

- 未ログイン状態で保護されたページにアクセスした場合 → ログイン画面にリダイレクト

## 受け入れ条件（Gherkin）

```gherkin
Scenario 1: 正常にログインできる
  Given 有効なアカウントが存在する
  When 正しい認証情報を入力してログインを実行する
  Then セッションが確立される
  And 村一覧画面にリダイレクトされる

Scenario 2: 誤った認証情報ではログインできない
  Given ログイン画面が表示されている
  When 誤った認証情報を入力してログインを実行する
  Then エラーメッセージが表示される
  And セッションは確立されない

Scenario 3: 未ログイン状態での保護ページアクセス
  Given セッションが存在しない
  When 村一覧画面にアクセスする
  Then ログイン画面にリダイレクトされる

Scenario 4: ログアウトできる
  Given ユーザーがログインしている
  When ログアウトを実行する
  Then セッションが破棄される
  And ログイン画面にリダイレクトされる
```

## ルール（Example Mapping）

- Rule 1: 認証が必要なページは未ログイン時にリダイレクト
  - Example: 未ログインで村一覧にアクセス → ログイン画面へ
- Rule 2: 誤った認証情報はエラーを表示（詳細は明かさない）
  - Example: 存在しないユーザー → 「認証情報が正しくありません」と表示
- Rule 3: ログアウト後はセッションを完全に破棄する
  - Example: ログアウト後にブラウザバックしても再ログインを要求

## 不明点 / 質問

- 認証方式は何か？（メール+パスワード / IDプロバイダー連携 など）
- セッションの有効期限はあるか？
- ユーザー登録機能は別PBIで追加するか、初期データとして用意するか？
