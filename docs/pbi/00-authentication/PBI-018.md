# PBI-018 — モックログイン E2E テストのフレーキーを修正する

## 背景

PBI-014（ログイン機能）の実装後、E2E テスト `auth.spec.ts` の test 2
「tenant_user でモックログインすると /villages にリダイレクトされること」が
フレーキー（成功することも失敗することもある）な状態になっている。

他の 4 件のテストは安定して通過する。

## 受け入れ条件

- `npm run test:e2e:mock` を 3 回連続で実行したとき、全 5 件が毎回通過すること

## 現象

- ボタンクリック後に URL が `/login` のままになる（`/villages` にリダイレクトされない）
- 約 5 秒のタイムアウトが発生する
- 他の tenant_admin / servicer_admin のテストは同じフローで安定通過

## 調査済みの内容

### 試した修正（改善せず）

1. `useAuthStore.login()` の戻り値を `Promise<AuthUser>` に変更し、ストア状態の再読み取りを廃止
2. v-select を `Escape` で明示的に閉じてからボタンをクリック
3. `resolveUser()` ヘルパー関数を使って実行時プロパティチェック

### 推測される根本原因

以下のいずれか、またはその組み合わせ：

1. **Vite コールドスタート時の遅延**
   - テスト 2 は全テスト中で最初に `LoginView.vue` のボタンをクリックする
   - `test 1` 実行中に `Failed to fetch dynamically imported module: LoginView.vue` エラーが発生しており、
     Vite がコールドスタート時にモジュールを提供できない瞬間がある可能性
   - test 3 以降は Vite がモジュールをキャッシュしているため安定

2. **Vue Router ナビゲーションガードのタイミング**
   - `router.push('/villages')` 呼び出し直後に `beforeEach` ガードが
     `authStore.user` を読むタイミングで、Pinia の reactive state が
     未確定の状態になる可能性

3. **MSW サービスワーカーの初期化タイミング**
   - `main.ts` の `await worker.start()` が返った後も、
     サービスワーカーが完全に有効化されるまでの間に
     ページが初期化されてしまう可能性（ただし mock auth は localStorage 依存のため影響は低いと推測）

## 調査アプローチ（未実施）

- Playwright の `--trace on` オプションでトレースを取得し、何が起きているかを可視化する
- `playwright.mock.config.ts` に `webServer.waitUntil: 'networkidle'` または
  `beforeAll` で追加のウォームアップを追加する
- `playwright.config.ts` の `retries: 1` を設定してフレーキーの頻度を計測する
