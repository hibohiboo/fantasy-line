# PBI-019 API フォルダ構成を feature 別に再編する

## ユーザーストーリー

As a 開発者
I want `apps/api/src/handlers/` という技術レイヤー別フォルダをなくし、機能別フォルダ構成に移行したい
So that 指針（`.claude/instructions/api.md`）に沿った構成になり、機能の追加・変更・削除がやりやすくなる

## 背景 / 目的

現在 `apps/api/src/handlers/*.ts` という技術レイヤー別フォルダに全ハンドラーが置かれている。
これは `.claude/instructions/api.md §12` の「`handlers/` や `services/` などの技術レイヤー別フォルダをトップレベルに作らない」に違反している。

また、テストが `apps/api/tests/handlers/` に分離されており、`folder-structure.md §4` の「関連ファイルは近接配置する」にも違反している。

PBI-001・PBI-003 完了後に規約整備が行われたため、既存コードが規約成立前の構成のまま残っている。

## スコープ

- 含む
  - `apps/api/src/handlers/*.ts` を機能別フォルダ（`src/<feature>/handler.ts`）に移動
  - `apps/api/tests/handlers/*.test.ts` を対応する `src/<feature>/` に移動
  - `apps/api/tests/small/` 配下のテストを `src/shared/` 相当に移動
  - `apps/api/tests/integration/` を `src/<feature>/` に移動
  - 全 import パスの更新
  - `apps/api` の `tsconfig.json` / `vitest.config.ts` / `package.json` のパス設定更新
- 含まない
  - `apps/api/src/db/` の移動（DB スキーマ・クライアントは現在の位置を維持）
  - `apps/api/src/http.ts`・`src/auth.ts`・`src/logger.ts` の削除（`src/shared/` に移動のみ）
  - ロジックの変更（純粋なファイル移動とパス更新のみ）

## ユースケース

### メイン

1. 開発者が village 機能を追加・変更する際、`src/village/` を見れば実装とテストが揃っている
2. 開発者が resident 機能を削除する際、`src/resident/` を丸ごと削除すれば済む

