# PBI-021 vue-router 5 と @vue/test-utils 2 の型不整合を解消する

## ユーザーストーリー

As a 開発者
I want `npm run build`（`vue-tsc --build`）が型エラーなしで通過してほしい
So that CI の型チェックが信頼できるものになり、リグレッションを早期に検出できる

## 背景 / 目的

`vue-router` ^5.1.0 と `@vue/test-utils` ^2.4.10 の間に型の不整合がある。
`createRouter()` の戻り値（`RouterClassic` 型）が、`@vue/test-utils` の `mount()` の
`global.plugins` が期待する `Plugin | [Plugin, ...any[]]` に代入できない。

テスト自体は vitest で全通過するが、`vue-tsc --build` が以下のエラーを 5 件出す。

```
src/features/resident/ResidentCreateView.medium.spec.ts(36,9):
  error TS2322: Type 'RouterClassic' is not assignable to type 'Plugin | [Plugin, ...any[]]'
src/features/resident/ResidentListView.medium.spec.ts(55,9): ...（同上）
src/features/resident/VillageResidentListView.medium.spec.ts(53,9): ...（同上）
src/features/village/VillageCreateView.medium.spec.ts(31,9): ...（同上）
src/features/village/VillageListView.medium.spec.ts(36,9): ...（同上）
```

`vue-router` 5 は PBI-020 リファクタリング前から導入済みであり、
型エラーもリファクタリング前から存在していた既存問題。

## スコープ

- 含む
  - エラーが出ている 5 つのテストファイルの修正
  - `@vue/test-utils` の最新版確認（型定義が vue-router 5 対応済みかを確認する）
  - 対応策の選択と実施（下記「対応方針の選択肢」を参照）
- 含まない
  - テストロジック・振る舞いの変更
  - `vue-router` / `@vue/test-utils` 以外のパッケージのアップグレード
  - E2E テストへの影響（Playwright は型チェック対象外）

## 対応方針の選択肢

| 案 | 内容 | メリット | デメリット |
|---|---|---|---|
| A: `@vue/test-utils` をアップグレード | `@vue/test-utils` の最新版が vue-router 5 の型に対応していれば適用 | 根本解消 | バージョンによる破壊的変更リスク |
| B: テストファイルに型アサーション追加 | `makeRouter() as Plugin` などでキャストし型エラーを回避 | 変更最小・安全 | 型安全性が下がる（`// eslint-disable` も必要になる場合あり） |
| C: `makeRouter()` のラッパー関数で型を吸収 | テストヘルパーに型を整合させたラッパーを置く | テストコードをクリーンに保てる | ラッパーのメンテコスト |

推奨は **A → なければ B** の順で調査・適用する。
