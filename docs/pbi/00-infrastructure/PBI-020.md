# PBI-020 フロントエンドフォルダ構成を features 別に再編する

## ユーザーストーリー

As a 開発者
I want `apps/frontend/src/` の技術レイヤー別フォルダ（`components/`・`views/`・`stores/`・`composables/`）をなくし、機能別フォルダ構成に移行したい
So that 指針（`.claude/instructions/frontend.md`）に沿った構成になり、機能の追加・変更・削除がやりやすくなる

## 背景 / 目的

現在 `apps/frontend/src/` は以下の技術レイヤー別フォルダ構成になっている。

```txt
src/
  components/village/
  components/resident/
  views/VillageListView.vue
  views/VillageCreateView.vue
  views/ResidentListView.vue
  views/ResidentCreateView.vue
  views/VillageResidentListView.vue
  stores/village.ts
  stores/resident.ts
  composables/useApiState.ts
```

これは `.claude/instructions/frontend.md §11` の「`src/features/<機能>/` に UI、データ取得、型、schema をまとめる」に違反している。

PBI-001・PBI-003 完了後に規約整備が行われたため、既存コードが規約成立前の構成のまま残っている。

## スコープ

- 含む
  - 機能別ファイルを `src/features/<機能>/` 配下に移動
  - `src/shared/ui/` にサイト共通 UI（`HomeView.vue` 等）を整理
  - 全 import パスの更新（`@/stores/` → `@/features/village/` 等）
  - テストファイルの移動（`views/__tests__/` → 対応する `features/<機能>/` に移動）
  - `vitest.config.ts` / `tsconfig` のパス設定確認・更新
- 含まない
  - `src/router/index.ts` の移動（`src/router/` を維持）
  - `src/mocks/` の移動（`src/mocks/` を維持）
  - `src/assets/` の移動（`src/assets/` を維持）
  - ロジックの変更（純粋なファイル移動とパス更新のみ）

## ユースケース

### メイン

1. 開発者が village 機能を追加する際、`src/features/village/` を見れば View・コンポーネント・ストア・テストが揃っている
2. 開発者が resident 機能を変更する際、`src/features/resident/` を探せばよい
