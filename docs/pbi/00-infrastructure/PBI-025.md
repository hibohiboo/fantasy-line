# Serena MCP サーバーの採用可否を判断する

## ユーザーストーリー

As a 開発者  
I want Serena MCP サーバーを継続使用すべきか削除すべきかを判断できる材料と基準を持ちたい  
So that 無駄なトークン消費を避けつつ、AI 支援の恩恵を最大化できる

---

## 背景 / 目的

現在このプロジェクトでは Serena MCP サーバーを導入している。  
2 つの相反する情報がある。

- **記事 A（note）**: MCP を導入すると、セッション開始前にツール説明文の読み込みで  
  **66,000 トークン**が消費される。Claude Code 2.x の標準機能（Explore エージェント・`/memory`・CLAUDE.md）で  
  代替可能であり、「シンプルな構成 = 安定 + 節約」として Serena を削除した。  
  URL: https://note.com/euro0202/n/na6551077349a

- **記事 B（Qiita）**: Serena を有効化すると出力トークンが約 43% 削減、  
  総コストが約 56% 削減された（単一プロジェクトでの簡易計測）。  
  プロジェクト知識の再利用により、不要なファイル読み込みが減る効果がある。  
  URL: https://qiita.com/YasuhiroKawano/items/27edcee5e4e6aed26306

どちらが本プロジェクトに適切かを判断できる状態にすることが目的。  
本プロジェクトは **AWS コスト最優先**・個人学習プロジェクトであり、CI/CD や長時間セッションより  
短時間の機能実装セッションが中心。

---

## スコープ

- 含む
  - Serena MCP サーバーのトークン消費構造の整理（起動時 vs セッション中）
  - Claude Code 2.x 標準機能（Explore / `/memory` / CLAUDE.md）との機能比較
  - 本プロジェクトの実際のセッション傾向でどちらが有利かの判断基準策定
  - 採用継続 or 削除の決定と `.claude/settings.json` への反映
  - 判断記録を ADR として残す

- 含まない
  - Serena 以外の MCP サーバーの評価
  - 他プロジェクト・他モデルへの汎化検証
  - Serena の機能拡張・カスタマイズ

---

## ユースケース

### メイン（削除を選択する場合）

1. 記事 A の主張（セッション開始前の固定トークン消費）を本プロジェクトで確認する
2. Claude Code 2.x 標準機能で Serena の代替が可能かを確認する
3. `.claude/settings.json` から Serena MCP エントリを削除する
4. 削除後のセッションでトークン消費量が減ることを確認する
5. ADR に判断根拠を記録する

### メイン（継続を選択する場合）

1. 記事 B の主張（43% 削減）が本プロジェクトの規模・セッション長で成立するか検証する
2. 起動時トークン消費と削減効果のトレードオフを計算する
3. ADR に継続根拠と監視条件を記録する

### 代替

- セッション長が短い（10〜20 ターン未満）場合は削除が有利と判断する
- セッション長が長い（50 ターン超）場合は継続が有利と判断する

### 例外

- 測定環境が本番とかけ離れている場合は、簡易比較ではなく条件を明記した上で判断する

## 受け入れ条件（Gherkin）

```gherkin
Scenario 1: トレードオフ判断基準が明文化されている
  Given Serena 導入時の起動コスト（ツール説明文トークン数）と削減効果が整理されている
  When 本プロジェクトの典型的なセッション長（ターン数・入力規模）を当てはめる
  Then どちらが有利かを「セッション X ターン超なら継続、未満なら削除」の形式で表現できる

Scenario 2: 採用可否の決定が ADR に記録されている
  Given 判断基準に基づいて採用継続 or 削除を決定した
  When ADR を `docs/adr/` に作成する
  Then 背景・決定・採用理由・代替案・採用しない条件・見直し条件がすべて含まれる

Scenario 3: 削除を選択した場合の設定変更が完了している
  Given ADR で削除と決定した
  When `.claude/settings.json` を更新する
  Then Serena MCP エントリが削除されており、他の MCP 設定に影響していない
  And 次のセッション開始時に Serena 由来のトークン消費がなくなっている

Scenario 4: 継続を選択した場合の監視条件が決まっている
  Given ADR で継続と決定した
  When ADR の「見直し条件」セクションを記述する
  Then 「月額コストが X 円を超えたら見直す」などの具体的なトリガが明記されている
```

---

## ルール（Example Mapping）

- **Rule 1: 起動コストと削減効果のどちらが大きいかで決める**
  - Example: セッション 10 ターン、1 ターン平均 500 トークン削減 → 削減 5,000 トークン < 起動 66,000 トークン → 削除
  - Example: セッション 200 ターン、1 ターン平均 500 トークン削減 → 削減 100,000 トークン > 起動 66,000 トークン → 継続

- **Rule 2: Claude Code 2.x 標準機能で代替できるなら削除を優先する**
  - Example: Explore エージェント・`/memory`・CLAUDE.md でコード調査・知識保存ができる → 削除候補
  - Example: Serena でしか実現できない機能（シンボル検索の高精度化等）が必要 → 継続候補

- **Rule 3: 判断は ADR に残す（レビュー可能にする）**
  - Example: `docs/adr/ADR-XXX-serena-mcp-evaluation.md` を作成し、背景・決定・代替案を含める

- **Rule 4: 本プロジェクトは AWS コスト最優先**
  - Example: トークン削減効果が不確かな場合は、シンプル構成（削除）を優先する

## 不明点 / 質問

- 本プロジェクトの典型的な 1 セッションのターン数（10〜20 程度？ 50 超？）は確認が必要
- 記事 B の「43% 削減」は Sonnet 4.5 での計測。現在使用中の Sonnet 4.6 でも同様の傾向か？
- Serena の `initial_instructions` ツール呼び出しが CLAUDE.md の instructions と重複していないか確認が必要

## INVEST チェック

- **Independent**: OK（他 PBI に依存しない。設定変更のみで完結）
- **Negotiable**: OK（削除 or 継続どちらの結論でも PBI として成立する）
- **Valuable**: OK（個人プロジェクトでも月数百円のコスト差が積み重なる。判断根拠の明文化が資産になる）
- **Estimable**: OK（記事 2 本の読み込み + 試算 + ADR 作成。0.5〜1 日程度）
- **Small**: OK（実装作業はなく、調査・判断・設定変更・ADR 作成のみ）
- **Testable**: OK（Scenario 1〜4 の Gherkin で検証可能）
