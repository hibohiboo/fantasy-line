# PBI-023 screen/home.md から実装詳細を除去し「仕様の合意記録」に再編する

## ユーザーストーリー

As a 開発者
I want `docs/design/detail/screen/home.md` を「何を・なぜ作るか」の合意記録として読めるようにしたい
So that コンポーネント名や実装コードが変わるたびにドキュメントを直す手間がなくなり、仕様の本質が読み取れるようになる

## 背景 / 問題

PBI-022 で `docs/design/detail/` 配下の village・resident 系ドキュメントを「仕様の合意記録」に再編したが、
同じ方針が `docs/design/detail/screen/home.md` には適用されていない。

### 具体的な違反箇所

**`docs/design/detail/screen/home.md`**

| 違反の種類 | 内容 |
|---|---|
| コンポーネント名を含む見出し | `## トップページ（\`HomeView.vue\`）` |
| コンポーネント名を含む見出し | `## アプリケーションレイアウト（\`App.vue\`）` |
| 実装コード | `### コンポーネント構成` — ASCII コンポーネントツリー（Vuetify タグ・CSS クラス名の羅列） |
| 実装コード | `### 認証状態の判定` — TypeScript コードブロック（`localStorage.getItem` の具体的な実装） |
| 実装コード | `### 「始める」ボタンの処理` — TypeScript コードブロック（`start()` 関数の具体的な実装） |
| 実装コード | `## アプリケーションレイアウト > ### 構成` — ASCII コンポーネントツリー |

### 違反が引き起こす問題

- PBI-022 の適用後も `home.md` だけ旧形式が残り、ドキュメント間で記述方針が不統一になる
- コンポーネント名や実装が変わったときに `home.md` だけ手動更新が必要になる

## スコープ

### 含む

- `docs/design/detail/screen/home.md` の再編

### 含まない

- `docs/design/style-guide.md` — スタイルガイドは実装指針を扱う文書のため対象外
- ロジックや実装の変更（ドキュメントのみの改訂）
- PBI-022 で対応済みの他ドキュメント

## 変更方針

### 削除するもの

- ASCII コンポーネントツリーのコードブロック（`HomeView.vue` 構成・`App.vue` 構成）
- TypeScript コードブロック（`localStorage.getItem` 代入・`start()` 関数）
- コンポーネント名を含むセクション見出し（`（\`HomeView.vue\`）`・`（\`App.vue\`）` の括弧部分）

### 残すもの（仕様・判断として適切なもの）

- 認証状態の判定ロジックの**仕様**（`userId` の有無で表示を切り替えるという振る舞いの説明）
- 「始める」ボタンの処理手順（`localStorage` に保存して遷移する、という仕様の文章）
- バリデーションの判断理由（「シンプルなボタン制御で十分のためフォームバリデーションは使用しない」という意図）
- ナビゲーションの振る舞い（未ログイン時のリダイレクト方針）

### 変換例

**Before（実装指示書）:**

```markdown
## トップページ（`HomeView.vue`）

### 認証状態の判定

`localStorage.getItem('userId')` の有無で未ログイン／ログイン済みを切り替える。

\`\`\`typescript
const userId = ref(localStorage.getItem('userId'))
\`\`\`

`userId` が `null` → 未ログイン表示（ユーザー名入力フォーム）
`userId` が文字列 → ログイン済み表示（「村一覧を見る」ボタン）
```

**After（仕様の合意記録）:**

```markdown
## トップページ

### 認証状態の判定

ローカルストレージに保存されたユーザー ID の有無で表示を切り替える。

- ユーザー ID が未保存: ユーザー名入力フォームを表示する
- ユーザー ID が保存済み: 「村一覧を見る」ボタンを表示する
```

## 受け入れ条件（Gherkin）

```gherkin
Scenario 1: コンポーネント名が見出しに残っていない
  Given 再編後のドキュメントが存在する
  When ドキュメントを通読する
  Then `HomeView.vue` や `App.vue` などのファイル名が見出しに登場しない

Scenario 2: 実装コードが残っていない
  Given 再編後のドキュメントが存在する
  When ドキュメントを通読する
  Then TypeScript のコードブロックが登場しない
  And ASCII コンポーネントツリーのコードブロックが登場しない

Scenario 3: 仕様の判断理由が読み取れる
  Given 再編後のドキュメントが存在する
  When 認証状態判定・「始める」ボタン処理・バリデーション方針の箇所を読む
  Then 各判断の理由が文章として書かれている
```
