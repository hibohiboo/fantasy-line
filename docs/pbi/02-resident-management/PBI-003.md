# PBI-003 住人を登録する

## ユーザーストーリー
As a 管理者（村のオーナー）
I want 自分の村に住人を名前・読み・生年月日で登録したい
So that 村のメンバーを構成し、年齢ライフサイクルを用いたシミュレーションに活用できる

## 背景 / 目的
村（PBI-001）が作成できるようになった次のステップとして、村の構成員である住人を登録できる必要がある。
生年月日はシミュレーション（PBI-007）において年齢ごとのライフサイクル（労働力・消費など）を算出する目安として使用する。
まずは最小限の情報（名前・読み・生年月日・所属村）で登録できるようにし、詳細情報は PBI-004 で拡充する。

## スコープ
- 含む
  - 住人の新規登録（名前・読み（カタカナ）・生年月日・所属村ID）
  - 住人一覧の表示（独立した住人管理ページ、読み昇順）
  - バリデーション（名前必須・文字数制限・読み必須・カタカナ形式・生年月日必須）
  - 権限制御（自分の村にのみ登録可能）
- 含まない
  - 職業・性格タグの設定（→ PBI-004）
  - 住人の削除・編集（→ 別PBI。削除は物理削除方針、紐づくデータも全消し、削除前バックアップDL機能も検討）
  - ページネーション（→ 性能要件確定後）
  - 生年月日を使った年齢計算・シミュレーション反映（→ PBI-007）

## ユースケース
### メイン
1. 管理者が住人管理ページ（`/residents`）を開く
2. 「住人を追加」ボタンを押し、住人登録フォームに遷移する
3. 名前・読み（カタカナ）・生年月日・所属村を入力する
4. 「登録」ボタンを押す
5. 住人が村に紐づいて保存される
6. 住人一覧画面に戻り、登録した住人が読み昇順で表示される

### 代替
- 住人一覧が空の場合は「住人が登録されていません。追加してください」と表示する

### 例外
- 名前が空の場合はバリデーションエラーを表示し、送信を阻止する
- 名前が128文字を超える場合はバリデーションエラーを表示する
- 読みが空の場合はバリデーションエラーを表示する
- 読みがカタカナ以外の文字を含む場合はバリデーションエラーを表示する
- 生年月日が未入力の場合はバリデーションエラーを表示する
- 他ユーザーの村に住人を登録しようとした場合は 403 エラーを返す
- 未認証状態で API を呼び出した場合は 401 エラーを返す

## ルール（Example Mapping）

- Rule 1: 住人名は1文字以上128文字以内である
  - Example: 「タロウ」(3文字) → OK
  - Example: 空文字 → NG（必須エラー）
  - Example: 129文字の名前 → NG（文字数超過エラー）

- Rule 2: 読みはカタカナのみ、1文字以上128文字以内である
  - Example: 「タロウ」 → OK
  - Example: 「たろう」（ひらがな）→ NG（カタカナエラー）
  - Example: 空文字 → NG（必須エラー）

- Rule 3: 生年月日は必須である（シミュレーションで年齢ライフサイクルの目安に使用）
  - Example: 「2000-01-15」入力 → OK
  - Example: 未入力 → NG（必須エラー）

- Rule 4: 住人は必ず1つの村に所属する
  - Example: villageId を指定して登録 → 村に紐づいて保存
  - Example: villageId なしで API を呼び出す → 400 Bad Request

- Rule 5: 自分の村にのみ住人を登録できる（村のオーナー権限）
  - Example: 自分の村 → 登録成功
  - Example: 他ユーザーの村 → 403 Forbidden

- Rule 6: 同名の住人を同じ村に複数登録できる（一意制約なし）
  - Example: 同名・異なる生年月日 → どちらも保存される

- Rule 7: 住人一覧は読み（カタカナ）の昇順で表示する
  - Example: 「ジロウ」「アキコ」「タロウ」登録済み → 「アキコ」→「ジロウ」→「タロウ」順

- Rule 8: 1村あたりの住人数に上限はない

## 依存関係

- **先行**: PBI-001（村を作成する）— villages テーブルが存在している必要がある
- **後続**: PBI-004（住人の詳細情報を編集する）— 職業・性格タグの追加
- **後続**: PBI-007（1日シミュレーション）— 住人の生年月日（年齢）をライフサイクル計算に使用

## INVESTチェック
- Independent: OK（PBI-001完了後に単独で実装可能）
- Negotiable: OK（読みの文字数制限・カタカナ限定などは交渉可能）
- Valuable: OK（住人なしにシミュレーションができないため、MVP の核心）
- Estimable: OK（PBI-001 の実装パターンをそのまま踏襲できるため見積もりやすい）
- Small: OK（名前・読み・生年月日・村IDのみの最小実装。詳細は PBI-004 に分離済み）
- Testable: OK（Gherkin シナリオで検証可能。PBI-001 のテスト構造を再利用可能）
