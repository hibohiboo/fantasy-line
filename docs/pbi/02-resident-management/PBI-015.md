# PBI-015 住人を削除する

## ユーザーストーリー
As a 管理者（村のオーナー）
I want 不要になった住人を村から削除したい
So that 村の構成員を正確に管理できる

## 背景 / 目的
登録ミスや設定変更により不要になった住人を削除できる必要がある。
削除は物理削除とし、紐づく関連データ（シミュレーション結果・職業設定など）もすべて消去する。
データ喪失リスクに備え、削除前に紐づくデータ一式をファイルにDLしてバックアップできる仕組みも提供する（なおよし）。

## スコープ
- 含む
  - 住人の物理削除（紐づく関連データもすべて削除）
  - 削除確認ダイアログの表示
  - 権限制御（自分の村の住人のみ削除可能）
- 含まない（なおよし・別途検討）
  - 削除前の関連データ一式バックアップDL機能
- 含まない
  - 論理削除（削除フラグによる非表示）
  - 一括削除
  - 削除後の復元

## ユースケース
### メイン
1. 管理者が住人一覧または住人詳細画面で「削除」ボタンを押す
2. 確認ダイアログが表示される（「この住人と紐づくデータをすべて削除します。よろしいですか？」）
3. 管理者が「削除する」を押す
4. 住人と紐づく関連データが物理削除される
5. 住人一覧に戻り、削除した住人が表示されなくなる

### 代替
- 確認ダイアログで「キャンセル」を押した場合は削除せず一覧に戻る

### 例外
- 他ユーザーの村の住人を削除しようとした場合は 403 エラーを返す
- 未認証状態で API を呼び出した場合は 401 エラーを返す
- 存在しない住人IDを指定した場合は 404 エラーを返す

```gherkin
  Given 管理者がログインしており、住人「タロウ」が存在する
  When 管理者が削除ボタンを押し、確認ダイアログで「キャンセル」を押す
  Then 「タロウ」は削除されない
  And 住人一覧に「タロウ」が表示されたままである

Scenario 3: 住人に紐づく関連データもすべて削除される
  Given 住人「タロウ」にシミュレーション結果・職業設定などの関連データが存在する
  When 管理者が「タロウ」を削除する
  Then 「タロウ」本体と関連データがすべて物理削除される

Scenario 4: 他ユーザーの村の住人は削除できない
  Given 別ユーザーが所有する村「よその村」に住人「ジロウ」が存在する
  When 管理者が「ジロウ」を削除しようとする
  Then 403 エラーが返される
  And 「ジロウ」は削除されない

Scenario 5: 存在しない住人を削除しようとすると 404 が返る
  Given 管理者がログインしている
  When API に存在しない住人IDで削除リクエストを送信する
  Then 404 Not Found が返される
```

## ルール（Example Mapping）

- Rule 1: 削除は物理削除である（論理削除フラグは使わない）
  - Example: 住人を削除 → DB から行が消える

- Rule 2: 住人に紐づく関連データもすべて物理削除する
  - Example: シミュレーション結果・職業設定が存在する住人を削除 → 関連データも全消去

- Rule 3: 削除前に確認ダイアログを表示する
  - Example: 削除ボタン押下 → ダイアログ表示 → 「削除する」押下 → 削除実行
  - Example: 削除ボタン押下 → ダイアログ表示 → 「キャンセル」押下 → 削除しない

- Rule 4: 自分の村の住人のみ削除できる
  - Example: 自分の村の住人 → 削除成功
  - Example: 他ユーザーの村の住人 → 403 Forbidden
