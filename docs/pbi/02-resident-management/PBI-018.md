# PBI-018 PBI-003 コードレビュー指摘事項の対応

## ユーザーストーリー

開発者として、PBI-003 のコードレビューで検出された P2/P3 指摘事項を解消したい。
そうすることで、コードの堅牢性と保守性を向上できる。

## 背景

PBI-003（住人を登録する）のレビュー（2026-05-17）で以下の指摘が挙がった。
いずれもマージブロッカーではないが、品質向上のために対応する。

## 受け入れ条件

### P2 — Medium

- [ ] `listVillageResidents.ts`: `villageId` が NaN の場合に 400 Bad Request を返す
  - `Number(event.pathParameters?.id)` が NaN のとき、現状は 403 を返す（DB での WHERE 不一致）
  - 正しくは `!Number.isInteger(villageId) || villageId < 1` で 400 を返す

- [ ] フロントエンド View の `as unknown as` キャスト除去
  - `ResidentListView.vue`・`VillageResidentListView.vue`・`VillageListView.vue` の storeToRefs 問題
  - `ResidentCreateView.vue`・`VillageCreateView.vue` の `store.error` 型問題
  - Pinia v3 の型推論に対応した適切な型付けに修正する

### P3 — Low

- [ ] `createResident.ts`: INSERT 後の SELECT で `created` が `undefined` の場合に 500 ガードを追加
- [ ] `logger.ts`: `LogFields` 型に `residentId?: number` を明示的に追加
- [ ] `useApiState.ts`: ストアインスタンスごとに `isLoading`/`error` が独立する設計意図をコメントで明記
- [ ] `resident.test.ts`: `./resident` の相対インポートを `@repo/schema` 経由に変更

## スコープ

### 含む

- 上記受け入れ条件の実装
- 対応するユニットテストの追加・修正

### 含まない

- 新機能の追加
- UI の変更
