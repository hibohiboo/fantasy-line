# 基本設計 — 村管理（village）

## 目的と背景

fantasy-line はファンタジー世界の村を「生きたシミュレーション」として体験できるサービスである。
住人・職業・シミュレーションはすべて「村」を起点に成立する。

本設計は、管理者（ゲームマスター）が村を作成・一覧表示できる最小機能を確立することを目的とする。
この機能がなければプロダクトのいかなる機能も動作しない。

## 対象読者

- プロダクトオーナー（受け入れ条件の確認）
- 開発者（実装方針の把握）
- レビュアー（設計妥当性の確認）

## 機能概要

| 機能 | 説明 |
|---|---|
| 村の作成 | 管理者が村名（最大128文字）を入力して村を作成する |
| 作成者の管理者登録 | 村作成時に、作成ユーザーを管理者として自動的に関連付ける |
| 村一覧表示 | ログイン中のユーザーが所有する村のみを一覧で表示する |
| 他ユーザーの村への編集ガード | 他ユーザーが所有する村の編集を拒否する |

**スコープ外（将来PBI）:**
- 村の詳細設定（昼夜サイクルなど） → PBI-002
- 村の削除・アーカイブ
- 複数管理者の設定
- ログイン機能 → PBI-014

## システム構成

```
Browser (Vue 3 + Pinia + Vue Router)
    │  POST /villages          GET /villages
    ▼
API Gateway
    │
    ▼
Lambda (Node.js)
  ├── createVillage handler    … バリデーション → DB 書き込み
  └── listVillages  handler    … 認証ユーザーIDでフィルタ
    │
    ▼
Drizzle ORM ── Aurora MySQL (AWS RDS)
  └── villages テーブル
```

実装レベルの影響コンポーネント一覧は [詳細設計](../detail/village.md) の冒頭を参照すること。

## 主要なユースケースフロー

### メインフロー — 村を作成する

1. 管理者が「村を作成」ボタンを押す
2. 村名入力フォームが表示される
3. 村名を入力して「作成」ボタンを押す
4. フロントエンドがバリデーションを実行する（1〜128文字）
5. `POST /villages` にリクエストを送信する
6. API がバリデーションを実行し、村を DB に保存する
7. 作成ユーザーを管理者として villages テーブルに記録する
8. 村一覧画面に遷移し、新しい村が一覧に表示される

### 代替フロー — バリデーションエラー

- 村名が空の場合: フロントエンドでエラーメッセージを表示し、リクエストを送信しない
- 村名が129文字以上の場合: 同上
- API へのリクエストがバリデーション不備の場合: `400 Bad Request` を返し、フロントエンドがエラーを表示する

### 例外フロー — 未認証アクセス

- 未ログイン状態で村管理ページにアクセス → ログイン画面にリダイレクト
- 他ユーザーの村を編集しようとした場合 → `403 Forbidden` を返す

## データモデル概要

テーブル定義・ER図・CRUD表は [データモデル](../data-model/village.md) を参照すること。

**概要:**

- `villages` テーブルが中心エンティティ。`owner_id` によって認証ユーザーと 1:N で関連付けられる
- 同一ユーザーが同名の村を複数作成できる（ユニーク制約なし）
- 現時点で村管理が操作するテーブルは `villages` のみ（CRUD表は [データモデル](../data-model/village.md) 参照）

## 制約・前提条件

| 項目 | 内容 |
|---|---|
| 認証 | PBI-014（ログイン機能）が前提。MVP 開発中は認証モックを使用する |
| DB | Aurora MySQL Serverless V2 / ローカル開発は Docker MySQL 8.0 |
| 認証ユーザーID | API Gateway の authorizer またはリクエストヘッダー経由で取得（認証実装まではモック） |
| 村名スペースのみ許可可否 | 未確定（PBI-001 不明点より） |
