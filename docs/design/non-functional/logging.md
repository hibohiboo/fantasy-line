# ロギング方針

## 対象読者

API 担当の開発者。ログ実装時・障害調査時に参照すること。

---

## 最重要要件

**ユーザーの操作と、どの村で何が起きたかを追跡できること。**

すべてのAPIログに `userId`（操作したユーザー）と、村に関係する操作では `villageId` を含めること。
この2フィールドがなければ障害調査・監査が困難になるため、省略を禁止する。

---

## ログエントリの必須フィールド

| フィールド | 型 | 説明 | 必須条件 |
|---|---|---|---|
| `timestamp` | ISO 8601 文字列 | ログ出力日時 | 常に必須 |
| `level` | 文字列 | `INFO` / `WARN` / `ERROR` | 常に必須 |
| `message` | 文字列 | 人間が読める説明 | 常に必須 |
| `userId` | 文字列 | 操作したユーザーのID | 認証済みリクエストでは必須 |
| `villageId` | 数値 | 操作対象の村のID | 村に関する操作では必須 |
| `requestId` | 文字列 | リクエストの追跡ID（Lambda の requestId 等） | 常に必須 |

**出力形式: 構造化 JSON**

```json
{
  "timestamp": "2026-05-05T12:00:00.000Z",
  "level": "INFO",
  "message": "村を作成しました",
  "userId": "user-123",
  "villageId": 42,
  "requestId": "abc-def-123"
}
```

---

## ログレベル定義

| レベル | 使用場面 |
|---|---|
| `INFO` | 正常なユーザー操作（村の作成・一覧取得など） |
| `WARN` | 想定内の異常（バリデーションエラー・認可エラーなど） |
| `ERROR` | 想定外のエラー（DBエラー・未捕捉例外など） |

---

## ログ出力タイミング

| タイミング | レベル | 含めるフィールド |
|---|---|---|
| 村の作成成功 | INFO | userId, villageId（作成された村のID） |
| 村の作成失敗（バリデーション） | WARN | userId |
| 村一覧の取得 | INFO | userId |
| 認証エラー | WARN | requestId（userId は取得できない） |
| 認可エラー（他ユーザーの村へのアクセス） | WARN | userId, villageId（アクセスしようとした村のID） |
| DBエラー | ERROR | userId, villageId（判明している場合） |

---

## ログに出力してはいけない情報

- パスワード・トークン・秘密鍵などの秘密情報
- メールアドレス・氏名など個人を特定できる情報（userId は識別子のため出力可）
- リクエスト・レスポンスのボディ全体（必要なフィールドのみ個別に出力する）

---

## 実装の優先度

現時点（初期フェーズ）では詳細な実装より**フォーマットの統一を優先**する。
`console.log` でもフィールド構造を守れば許容する。
本格的なロギングライブラリ導入・CloudWatch 連携は利用者が増えた段階で実施する。
