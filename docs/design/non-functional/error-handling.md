# エラーハンドリング規約

## 対象読者

API・フロントエンド担当の開発者。新しいエンドポイントやUI実装時に参照すること。

---

## HTTP ステータスコード規約

| ステータス | 使用条件 |
|---|---|
| 200 OK | 正常取得・正常更新 |
| 201 Created | リソース新規作成成功 |
| 400 Bad Request | リクエストボディのバリデーションエラー、JSONパース失敗 |
| 401 Unauthorized | 認証されていない（トークン未提供・無効） |
| 403 Forbidden | 認証済みだが操作権限がない（他ユーザーのリソースへのアクセス） |
| 404 Not Found | 指定リソースが存在しない |
| 500 Internal Server Error | サーバー内部エラー（DBエラーなど）。詳細はログのみ、レスポンスには含めない |

---

## エラーレスポンス形式

すべての API エラーレスポンスは以下のいずれかの形式に統一する。

### バリデーションエラー（400）

フィールドごとのエラーメッセージを返す。

```json
{
  "error": {
    "fieldErrors": {
      "name": ["1文字以上で入力してください"]
    }
  }
}
```

### その他のエラー（400 / 401 / 403 / 404 / 500）

単一のエラーメッセージ文字列を返す。

```json
{
  "error": "Unauthorized"
}
```

**禁止事項:**
- 500 エラーのレスポンスにスタックトレース・DB エラー詳細・内部パスを含めない
- フィールドエラー以外で `fieldErrors` キーを使用しない
- エラー形式をエンドポイントごとに独自定義しない（必ずこの規約に従う）

---

## レイヤー別の責務

| レイヤー | 責務 |
|---|---|
| フロントエンド（入力時） | 送信前のバリデーション。エラーはフォーム下部に表示。API呼び出しは行わない |
| フロントエンド（APIレスポンス） | `fieldErrors` を解析してフィールドごとに表示。401はログイン画面リダイレクト。それ以外はトースト等で通知 |
| API（バリデーション） | Zod スキーマで検証し、失敗時は 400 + `fieldErrors` 形式で返す |
| API（認証チェック） | 未認証は 401。認証済みだが権限なしは 403 |
| API（DBエラー） | 500 を返す。詳細はログに記録し、レスポンスには含めない |

フロントエンドのバリデーションは UX のためであり、セキュリティの最終防衛線ではない。
API 側のバリデーションを必ず実施すること。
