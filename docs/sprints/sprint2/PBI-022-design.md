# PBI-022 設計ドキュメント — 設計書から実装詳細を除去し「仕様の合意記録」に再編する

Sprint 2 / 作成日: 2026-05-31

**想定読者**: 実装担当者（ドキュメント変換作業者）  
**目的**: 4ドキュメントの変換ルールを確認するリファレンス。Phase 3 の作業根拠として使う。  
**スコープ**: ドキュメントのみの改訂。実装コード・ロジックの変更は含まない。

---

## 背景と課題

`.claude/skills/doc-coauthoring/SKILL.md` の基本原則:

> - 設計ドキュメントは「仕様を明らかにした判断と合意の記録」である
> - 「実装の指示書」ではない
> - 実装が React でも Vue でも、ファイル名が変わっても意味を持つ内容だけを書く

現在の `docs/design/detail/` 配下 4 ドキュメントはこの原則に違反しており、
ファイルパスの列挙・実装コードブロック・コンポーネント名を含む見出し が混在している。
PBI-019・PBI-020 のリファクタリングのたびにパス更新が発生したのがその証左。

---

## 変換ルール

### 削除するもの（寿命が短い）

| 種類 | 例 |
|---|---|
| ファイルパスを列挙した「実装影響コンポーネント一覧」テーブル | `apps/api/src/village/createVillage.ts` 等 |
| TypeScript コードブロック | Zod スキーマ全体、Pinia ストアのシグネチャ |
| Drizzle ORM クエリコードブロック | `.select().from().orderBy()` 等 |
| Vue template / HTML コードブロック | `<v-text-field>` 等のテンプレート定義 |
| ファイル名・コンポーネント名を含むセクション見出し | `### VillageListView.vue`、`### Pinia ストア（apps/...）` 等 |
| バリデーション節のファイルパス参照 | `**バリデーション（packages/schema/src/village.ts）**` |

### 維持するもの（寿命が長い）

| 種類 | 例 |
|---|---|
| Mermaid シーケンス図 | 村作成・村一覧の処理フロー |
| API 仕様表 | URI / メソッド / ステータスコード / レスポンス形式 |
| バリデーションルール表 | フィールド別のルールと `fieldErrors` の構造 |
| エラーハンドリング方針表 | レイヤー別・エラー種別の対応一覧 |
| 「なぜ」が書かれている実装注意点 | ソート順の理由、権限チェック位置、タイムゾーン方針 |
| 画面の責務と構成（役割レベル） | 一覧・作成・空状態の表示条件など |

### 変換するもの（コードを除き概念で書き直す）

| Before（実装指示書） | After（仕様の合意記録） |
|---|---|
| `### Pinia ストア（apps/frontend/src/.../villageStore.ts）` + TypeScript コード | `### フロントエンドの状態管理` + 保持する状態と操作の文章説明 |
| `### VillageListView.vue` + コンポーネント構成コード | `### 村一覧画面` + 画面の責務と表示条件の文章 |
| Drizzle クエリコード + 判断理由の文章 | 判断理由の文章のみ（ソートルールの意図） |
| バリデーションのスキーマ駆動説明 + コード | 意図の文章のみ（コードは削除） |
