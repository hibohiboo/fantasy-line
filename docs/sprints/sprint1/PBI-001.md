#### `infra/test/infra.test.ts` 削除について

CDK init が自動生成したテンプレートファイル。中身はすべてコメントアウトされており、残っていたのは空の `test('SQS Queue Created', () => {})` のみで何も検証していなかった。また `@types/jest` が tsconfig の types に含まれていないため `npm run build` でも型エラーが出ていた。

CDK assertion テストの価値は「意図しないインフラ変更を検出すること」だが、このプロジェクトの現フェーズでは API テスト（medium / integration）と E2E テストで動作保証を行う方針であり、CDK テストを実装・保守するコストが便益を上回ると判断して削除した。インフラの構文エラーは `cdk synth` で検出できる。

## Drizzle ORM スキーマ（実装起点）

`apps/api/src/db/schema.ts` に以下を追加する。
実装後はコードが正本となるため、このスニペットは参照のみとする。

```typescript
export const villages = mysqlTable('villages', {
  id: serial('id').primaryKey(),
  name: varchar('name', { length: 128 }).notNull(),
  ownerId: varchar('owner_id', { length: 255 }).notNull(),
  createdAt: timestamp('created_at').notNull().defaultNow(),
});

export type Village = typeof villages.$inferSelect;
export type NewVillage = typeof villages.$inferInsert;
```

---

## Zod スキーマ（実装起点）

`packages/schema/src/village.ts` を新規作成する。

```typescript
import { z } from 'zod';

export const CreateVillageSchema = z.object({
  name: z.string().min(1).max(128),
});

export const VillageSchema = z.object({
  id: z.number(),
  name: z.string(),
  ownerId: z.string(),
  createdAt: z.date(),
});

export const CreateVillageResponseSchema = z.object({
  village: VillageSchema,
});

export const ListVillagesResponseSchema = z.object({
  villages: z.array(VillageSchema),
});

export type CreateVillageInput = z.infer<typeof CreateVillageSchema>;
export type Village = z.infer<typeof VillageSchema>;
export type CreateVillageResponse = z.infer<typeof CreateVillageResponseSchema>;
export type ListVillagesResponse = z.infer<typeof ListVillagesResponseSchema>;
```

## マイグレーション手順（PBI-001 用）

1. `apps/api/src/db/schema.ts` に上記の `villages` テーブル定義を追加する
2. `npx drizzle-kit generate` を実行して `apps/api/drizzle/0001_*.sql` を生成する
3. 生成された SQL を確認し、`villages` テーブルの CREATE 文が含まれていることを確認する（`owner_id` インデックスは現フェーズでは作成しない）
4. ローカル MySQL（Docker）で `npx drizzle-kit migrate` を実行して適用する

詳細な運用ルールは [マイグレーション方針](../../design/non-functional/migration.md) を参照すること。

## 認証モック方針（PBI-014 実装前）

PBI-014（ログイン機能）が未実装の間は、以下のモック方式で `owner_id` を取得する。

- ローカル/テスト: リクエストヘッダー `X-User-Id` の値を使用する
- 値が存在しない場合は固定値 `"mock-user-1"` にフォールバックする
- 本番切り替えは環境変数 `AUTH_ENABLED=true` を条件にする（PBI-014 で実装）
