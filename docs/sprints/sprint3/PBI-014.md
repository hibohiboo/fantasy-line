## authService.ts の実装詳細

```ts
export type UserType =
  | 'tenant_user'
  | 'tenant_admin'
  | 'servicer_admin'
  | 'servicer_delegate';

export interface AuthUser {
  userId: string;
  email: string;
  userType: UserType;
  tenantId?: string;
}

export interface AuthService {
  signIn(email: string, password: string): Promise<AuthUser>;
  signOut(): Promise<void>;
  getCurrentUser(): Promise<AuthUser | null>;
}
```

---

## authService.amplify.ts の実装詳細

- `signIn`: `aws-amplify/auth` の `signIn()` を呼び出す。成功後に `fetchAuthSession()` で ID トークンを取得し、`custom:user_type` / `custom:tenant_id` を抽出して `AuthUser` を構築する
- `signOut`: `aws-amplify/auth` の `signOut({ global: true })` を呼び出す（グローバルサインアウト）
- `getCurrentUser`: `aws-amplify/auth` の `fetchAuthSession()` を呼び出し、セッションが存在する場合は `AuthUser` を返す。セッションなしまたは例外時は `null` を返す

`custom:user_type` が想定 4 値以外の場合は `AuthUser` の構築を拒否し、例外を投げる（`auth-cognito.md` の例外方針に準拠）。

---

## authService.mock.ts の実装詳細

- `signIn`: 引数の `email` / `password` を無視し、固定 `AuthUser` を即座に返す
  - 選択されたユーザー種別は `localStorage.setItem('mock:userType', value)` で保持する（モックログイン画面からセット）
  - `tenant_*` の場合は `tenantId: "acme"` を付与する
  - `servicer_*` の場合は `tenantId: undefined`
- `signOut`: `localStorage.removeItem('mock:userType')` を実行する
- `getCurrentUser`: `localStorage.getItem('mock:userType')` が存在する場合に `AuthUser` を返す。なければ `null`

## useAuthStore.ts の実装詳細

```ts
// 状態
user: AuthUser | null = null
isLoading: boolean = false

// アクション
async login(email: string, password: string): Promise<void>
  // authService.signIn を呼び出し user を更新
  // 失敗時は例外をそのまま投げる（ログイン画面側でキャッチする）

async logout(): Promise<void>
  // authService.signOut を呼び出し user = null にリセット
  // router.push('/login') は呼び出し側の責務

async restoreSession(): Promise<void>
  // authService.getCurrentUser を呼び出し user を更新
  // 失敗時は user = null のままにする（例外を握りつぶす）
```

authService は `provide/inject` または `createPinia` の初期化時に注入する。
テストでは `authService` を差し替えてスパイできるようにする。

## LoginView.vue の実装詳細

### 通常モード（`VITE_USE_MOCK !== 'true'`）

- `<Authenticator :hideSignUp="true">` をレンダリングする
- slot の `default` に受け取った `user` を使って `authStore.login()` を呼び出し、
  `userType` に応じたルートへ `router.push()` する
- 日本語ローカライズは `i18n.ts` で定義した辞書を `Amplify.configure` 後に適用する

### モックモード（`VITE_USE_MOCK === 'true'`）

- Amplify Authenticator を使わず、独自のモックログインフォームを表示する
- ユーザー種別ドロップダウン（Vuetify `<v-select>`）と「モックログイン」ボタン（`<v-btn>`）
- ボタン押下で `authStore.login('', '')` を呼び出す（authService.mock が localStorage からユーザー種別を読んで返す）
- ログイン後は通常と同じリダイレクトロジックを通る

## router/index.ts の変更詳細

### 追加するルート

```ts
{
  path: '/login',
  name: 'login',
  component: () => import('../features/auth/LoginView.vue'),
}
```

### ルートガードの変更

```ts
// 変更前
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !localStorage.getItem('userId')) {
    return { name: 'home' }
  }
})

// 変更後
router.beforeEach(async (to) => {
  const authStore = useAuthStore()
  if (to.meta.requiresAuth && !authStore.user) {
    return { name: 'login' }
  }
})
```

アプリ起動時（`app.use(router)` の後）に `authStore.restoreSession()` を呼び出し、
`router.isReady()` を待ってから `app.mount('#app')` する。

## main.ts の変更詳細

```ts
async function bootstrap() {
  // 1. MSW（既存。変更なし）
  if (import.meta.env.VITE_USE_MOCK === 'true') {
    const { worker } = await import('./mocks/browser')
    await worker.start({ onUnhandledRequest: 'bypass' })
  }

  // 2. authService の DI
  const authServiceModule = import.meta.env.VITE_USE_MOCK === 'true'
    ? await import('./features/auth/authService.mock')
    : await import('./features/auth/authService.amplify')
  const authService = authServiceModule.createAuthService()

  // 3. Amplify 初期化（本番のみ）
  if (import.meta.env.VITE_USE_MOCK !== 'true') {
    const { Amplify } = await import('aws-amplify')
    const { I18n } = await import('aws-amplify/utils')
    const { translations } = await import('./features/auth/i18n')
    Amplify.configure({
      Auth: {
        Cognito: {
          userPoolId: import.meta.env.VITE_COGNITO_USER_POOL_ID,
          userPoolClientId: import.meta.env.VITE_COGNITO_CLIENT_ID,
        }
      }
    })
    I18n.putVocabularies(translations)
    I18n.setLanguage('ja')
  }

  // 4. Vue アプリ起動
  const app = createApp(App)
  const pinia = createPinia()
  app.use(pinia)
  app.use(router)
  app.use(vuetify)

  // 5. セッション復元（ルートガード前に必要）
  const authStore = useAuthStore()
  authStore.setAuthService(authService)
  await authStore.restoreSession()
  await router.isReady()

  app.mount('#app')
}
```

## テスト設計

### useAuthStore.small.spec.ts

| テスト名 | 検証内容 |
|---|---|
| `login() が成功したとき user がセットされること` | モック authService が AuthUser を返すと store.user に反映される |
| `login() が失敗したとき user が null のままであること` | モック authService が例外を投げると store.user は null のまま |
| `logout() 後に user が null になること` | logout() 後に store.user === null |
| `restoreSession() でセッションが復元されること` | getCurrentUser が AuthUser を返すと store.user に反映される |
| `restoreSession() でセッション切れのとき user が null のままであること` | getCurrentUser が null を返すと store.user は null のまま |

### authService.mock.spec.ts

| テスト名 | 検証内容 |
|---|---|
| `tenant_user を選択してログインすると tenantId が "acme" であること` | mock:userType=tenant_user の場合に tenantId を返す |
| `servicer_admin を選択してログインすると tenantId が undefined であること` | mock:userType=servicer_admin の場合に tenantId が undefined |
| `signOut() 後に getCurrentUser() が null を返すこと` | localStorage から mock:userType が消える |
