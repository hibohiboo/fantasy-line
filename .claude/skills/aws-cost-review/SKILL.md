# AWS コストレビュー Skill

このプロジェクトは個人で運用するため、AWS 利用料を低く抑えることが
最優先制約のひとつである。本 Skill は、コスト影響のある変更を見逃さない
ためのレビュー観点を定義する。

---

## 目的

- AWS リソース追加・変更で「気付かないうちに月額が跳ねる」状況を防ぐ
- 想定コストを ADR / PR 説明に残す習慣を作る
- 常時起動リソース・有料機能の導入条件を明確にする

## 使用するタイミング

- CDK で新規リソースを追加・変更するとき
- アクセス急増時の挙動を見直すとき
- ログ・メトリクス保持期間を変更するとき
- AWS Budgets のしきい値を見直すとき

## 手順

### 1. 大原則を確認する

- 本体は **S3 + CloudFront** で配信する（常時起動なし）
- 動的処理は Lambda の呼び出し時課金に留める
- NAT Gateway / ALB / ElastiCache / EC2 を作らない
- WAF / GuardDuty / Inspector など有料機能は ADR で導入条件を明示する

### 2. リソースタイプ別の観点

#### S3

- ストレージ階層（Standard / Standard-IA / Glacier）が用途に合っているか
- ライフサイクル（古いオブジェクトを削除 / アーカイブ）を設定しているか
- 不要なバージョニングを有効にしていないか
- ログバケットを本体バケットと分けているか

#### CloudFront

- キャッシュポリシーが妥当か（過小だと Origin にヒット過多、過大だと反映遅延）
- 価格クラスをブログの読者層に合わせて選ぶ
- CloudFront ログの保存量・期間を抑える

#### Lambda

- メモリは 128〜512MB から始め、計測してから増やす
- ARM64（Graviton）を既定にする
- タイムアウトを過剰に長くしない
- 想定呼び出し回数 × 月数で料金見積もりを出す

#### API Gateway

- HTTP API か REST API か（HTTP API の方が安価）
- リクエスト数の見積もりを残す
- 認証方法によって追加料金が出ないか確認する

#### CloudWatch Logs

- ロググループに保持期間を必ず設定する（30〜90 日目安）
- ログ取り込み量・ストレージのコスト感を把握する
- Logs Insights のクエリ頻度にも注意する

#### EventBridge / Schedule

- 過剰に短いインターバルで Lambda を呼び出していないか
- Dead Letter Queue / リトライ回数を意識しているか

### 3. AWS Budgets

- 月額予算と通知先を明示する
- 急増を即知らせるアラートを 50% / 80% / 100% など段階的に設定する
- 予算超過時に「とりあえず無視」しない（原因 PR・リソースの特定）

### 4. 想定コストを残す

リソース追加・変更 PR には次を残す。

- 想定月額レンジ（最良 / 想定 / 最悪）
- 主要なコストドライバ（呼び出し回数・転送量・ログ量等）
- 本番想定でも個人プロジェクト範囲に収まるか
- AWS Budgets と整合するか

### 5. 禁止事項を導入する場合

- VPC / NAT Gateway / WAF / RDS など常時課金が大きいものは ADR 必須
- 既定では作らず、必要性が立証されたときだけ採用する

## チェックリスト

CDK / インフラ変更時に確認する。

- [ ] 常時起動リソースを増やしていないか（NAT / ALB / RDS / EC2 / VPC を含む）
- [ ] S3 のライフサイクルが設定されているか
- [ ] CloudFront 価格クラスを意識しているか
- [ ] Lambda のメモリ・タイムアウト・アーキテクチャ（ARM64）を見直したか
- [ ] CloudWatch Logs / CloudFront ログの保持期間を明示したか
- [ ] AWS Budgets と整合する想定コストを書いたか
- [ ] WAF / GuardDuty 等の有料機能を入れる場合に ADR があるか
- [ ] 「コスト影響なし」と判断したなら、その根拠が PR に書かれているか

## 禁止事項

- 想定コストを書かずに常時起動リソースを追加する
- 「とりあえず VPC を作る」前提で設計する
- ログを「無期限」で保持する
- AWS Budgets を設定しないまま新リソースを増やす
- WAF / GuardDuty / Inspector / Security Hub を理由なし有効化する
- 個人アカウントで本番想定の負荷試験を行い課金を発生させる
