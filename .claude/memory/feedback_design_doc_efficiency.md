---
name: 設計ドキュメント効率化方針
description: 処理フロー図の書き方・共通パターンの参照方法・ドキュメント重複禁止の原則
type: feedback
---

詳細設計の処理フロー詳細では、共通パターンを繰り返し書かない。

**Why:** 認証・ユーザーID取得・権限チェックなどは毎エンドポイントで同じ構造になる。フロー図を都度書くと作成・読解コストが高く、変更時の漏れも生じる。

**How to apply:**

- `docs/design/non-functional/api-architecture.md` に代表パターン3種（書き込み / 所有権チェック付き書き込み / 読み取り）のシーケンス図を集約済み
- 各詳細設計（`docs/design/detail/*.md`）の「処理フロー詳細」セクションには、エンドポイントごとに「どの代表パターンを使うか」の対応表のみ置く
- エンドポイント固有の複雑さ（例: 複数テーブルへのJOINや複合トランザクション）がある場合のみ追加図を書く
- `docs/design/detail/village.md` が参考例（代表パターンへの参照のみ、フル図なし）

**対応表の書き方例:**

```markdown
| エンドポイント | 使用パターン |
|---|---|
| POST /api/residents | 代表パターン 2（認証 + 所有権チェック + 書き込み） |
| GET /api/residents  | 代表パターン 3（認証 + 読み取り）。JOIN で owner_id 絞り込み |
```
