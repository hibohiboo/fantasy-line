PBIドキュメントと実装差分をもとにレビューします。

# タスク

1. PBIドキュメント（受け入れ条件・スコープ）を読み込む
2. `git diff develop...HEAD` で実装差分を確認する
3. 実装計画チェックリストと照合する
4. 以下の観点でレビューを行う

## レビュー観点

### 機能面
- [ ] PBIの受け入れ条件（Gherkin）が全て満たされているか
- [ ] スコープ「含む」の全項目が実装されているか
- [ ] スコープ「含まない」の項目が混入していないか

### 品質面
- [ ] テストが網羅されているか（正常・代替・例外フロー）
- [ ] エラーハンドリングが適切か
- [ ] 型安全性が保たれているか

### 副作用
- [ ] 既存機能への影響はないか
- [ ] 破壊的変更がないか
- [ ] パフォーマンスへの影響はないか

# 出力形式

```
## レビュー結果

### 指摘事項
- [重要] ...
- [軽微] ...

### 実装漏れ
- ...

### 副作用リスク
- ...

### 総評
OK / 要修正
```

# 完了条件

- レビュー結果がチャットに出力されていること
- 「要修正」の場合は修正後に再レビューすること
- 完了後は「レビュー完了」とチャットに書き込むこと
