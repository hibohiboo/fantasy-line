# セキュリティ指針

このファイルはセキュリティに関する常時ルールを扱う。
詳細なレビュー手順は `.claude/skills/security-review/SKILL.md` を参照する。

---

## 1. 入力検証・出力エンコード

- すべての外部入力（ユーザー入力、API パラメータ、S3 JSON、環境変数）は `zod` で境界検証する
- 検証失敗時は 400 系で返し、内部詳細（スタックトレース・SQL・PII）を漏らさない
- 信頼できない HTML を生で挿入しない（Vue の `v-html` は原則使わない）
- 外部リンクには `rel="noopener noreferrer"` を付与する

## 2. Secrets 管理

- 秘密情報（API キー、トークン、接続文字列）をリポジトリに含めない
- `.env*` は必ず `.gitignore` に含める
- ログ・エラー応答に Secrets / PII が出ていないか常に確認する
- AWS Secrets Manager / Systems Manager Parameter Store を活用する

## 3. 認証・認可

- API エンドポイントごとに「誰が叩けるか」を明示する
- 認証なしで状態変更系エンドポイントを公開しない
- CDK / Lambda の IAM Role は最小権限にする（ワイルドカード `*` を避ける）
- S3 バケットの `blockPublicAccess` を必ず確認する

## 4. CDK / インフラ

- `cdk-nag` を導入し、警告を放置しない
- 公開バケットを意図せず作らない
- 抑制（suppression）を追加する場合は、理由・影響・見直し条件を必ず残す
- API Gateway + Lambda は OWASP ZAP の検査対象として扱う

## 5. 依存ライブラリ

- Dependabot / `npm audit` で脆弱性を定期確認する
- 新規ライブラリ導入時はライセンス・メンテナンス状況・セキュリティ影響を確認する

## 6. OWASP Top 10 常時意識

- **A03 インジェクション**: 文字列結合でクエリ・コマンドを作らない
- **A04 安全でない設計**: 権限分離と入力検証境界を設計段階から意識する
- **A05 セキュリティ設定ミス**: S3 公開設定、レスポンスヘッダ（HSTS 等）を確認する
- **A09 ログ・監視の不足**: 監査ログが落ちていないか定期確認する

## 7. やってはいけないこと

- `any` を使って型検証を回避する
- エラー応答にスタックトレース・SQL・内部 ID を含める
- IAM ワイルドカード（`Resource: "*"` / `Action: "*"`）を使う
- cdk-nag 警告を理由なしで suppression する
- ZAP / CodeQL の警告を一括無視する
